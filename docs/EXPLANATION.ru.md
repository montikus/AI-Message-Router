# Объяснение реализации

Приложение реализует маршрут из задания: HTTP → локальная LLM → вызов
инструмента агента → SMTP → письмо в Mailpit. Язык реализации — Python 3.13.

## Что происходит при запуске

Запуск из терминала WSL 2 выполняется той же единственной командой
`docker compose up -d` в каталоге проекта. Для текущего рабочего каталога путь
в WSL — `/mnt/c/Users/romch/OneDrive/Desktop/wskz`.
Нужен уже работающий Docker с доступом из WSL: при использовании Docker Desktop
это настраивается один раз в **Settings → Resources → WSL Integration**.
Устанавливать Python в WSL, создавать виртуальное окружение, запускать скрипты
инициализации или вручную скачивать модель не требуется.

Единственная обязательная команда — `docker compose up -d` из корня проекта.
Docker запускает Ollama и Mailpit. Одноразовый сервис `model-init` проверяет
наличие Qwen3 4B Instruct (`qwen3:4b-instruct-2507-q4_K_M`), автоматически
скачивает недостающие веса и выполняет пробный
вызов модели с инструментом. Пробный вызов не отправляет письмо.
Только после успешной инициализации стартует FastAPI.

Модель работает на CPU. GPU, облачный API и ключи доступа не нужны. Первый
запуск занимает время на загрузку образов и весов; повторный использует
сохранённые Docker volumes. Готовность проверяется через `/health/ready`.

## Как обрабатывается запрос

1. `POST /api/v1/messages` принимает JSON с `email` и `message`.
2. Pydantic проверяет адрес и непустую строку длиной до 4000 символов.
3. Агент отправляет текст в `/api/chat` Ollamy вместе с системными правилами
   классификации и JSON Schema инструмента `send_email`.
4. Модель возвращает нативный `message.tool_calls`, выбирая адрес отдела.
5. Приложение проверяет имя инструмента, единственность вызова и адрес из
   разрешённого списка. При ошибочном ответе модель получает одну попытку
   исправления. До успешной проверки SMTP не вызывается.
6. Агент выполняет `EmailTool.send_email`. Текст берётся из исходного запроса,
   `Reply-To` — из проверенного `email`, `From` — из настроек сервиса.
7. Mailpit принимает письмо. После подтверждения SMTP API возвращает `201`,
   выбранный адрес, идентификатор запроса и `Message-ID`.

Это настоящий tool calling: схема инструмента передаётся модели, модель
выбирает его аргумент, а исполнитель агента вызывает Python-функцию.
Текстовый ответ модели вроде «отправлено» не считается выполненным действием.
Получатель не вычисляется Python-кодом по ключевым словам.

## Почему выбран такой подход

FastAPI даёт валидацию и Swagger по требуемому адресу `/api/v1/docs`.
HTTPX используется для прямой интеграции с Ollama: для одного инструмента
не требуется дополнительный фреймворк агентов. Упомянутые в задании
Pydantic AI и LangChain — рекомендации, а не обязательные зависимости.

Инструмент принимает только получателя. Модель не может подменить исходное
сообщение, `Reply-To` или добавить произвольного адресата. После успешного
SMTP агент завершает работу, поэтому дополнительная генерация не может
вызвать повторную отправку или испортить подтверждённый результат.

Границы отделов в задании не определены. В проекте кадровое делопроизводство,
отпуска и зарплата направляются в `kadry`, подбор и развитие персонала — в HR.
Проблемы рабочего места — в help desk, инфраструктура компании — в IT.
Неопознанные темы — в `other`. Эти правила видны в README и системном prompt.

## Как проверить вручную

На вашем компьютере порт 8000 занят Apache. Поэтому в локальном `.env`
установлен `API_PORT=8001`: используйте <http://localhost:8001/api/v1/docs>.
В чистой копии проекта без `.env` стандартный порт — 8000.

Откройте Swagger по соответствующему адресу, выберите `POST /api/v1/messages`,
нажмите **Try it out** и передайте:

```json
{
  "email": "jan.nowak@example.com",
  "message": "Chciałbym zgłosić urlop na jutro"
}
```

Ожидаемый получатель — `kadry@example.com`. Письмо появится в
<http://localhost:8025>. В исходных заголовках письма будет
`Reply-To: jan.nowak@example.com`.

Автоматические тесты:

```bash
docker compose --profile test run --build --rm tests
docker compose exec api python scripts/smoke_test.py
```

## Практические ограничения

Качество классификации зависит от модели и неоднозначности текста. Температура
0 уменьшает вариативность, но не даёт универсальной гарантии правильности.
Если модель недоступна или не вызывает корректный инструмент, письмо не
отправляется; ошибка не маскируется маршрутизацией в `other`.

Ответ `201` означает подтверждение приёма Mailpit. Повторные HTTP-запросы
с одинаковым содержимым создают отдельные письма. При сетевой ошибке после
передачи SMTP результат может быть неопределённым, поэтому автоматических
повторов отправки нет. Для промышленного сервиса понадобились бы очередь,
хранилище состояния, идемпотентность и авторизация.
